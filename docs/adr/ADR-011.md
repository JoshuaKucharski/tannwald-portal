# ADR-011: Provider-Wechsel — DashScope (Qwen über API) neben Ollama, je Operation

**Status:** angenommen · Chat über DashScope (D2, Zugangsdaten des Betreibers 2026-11-02), Embeddings über Ollama `bge-m3`
(D11 Variante 2, Betreiber 2026-11-02 16:55 „wie deine Empfehlung“); Kostensatz bestätigt der Betreiber in Teil 4 v2 (Zeile 4d.8) · **Datum:** 2026-11-02 · **Quelle:**
RunBook Phase 2, Aufgabe 3.1 (Wahrheit 4, D2); ergänzt ADR-004

## Kontext

Der Hetzner-Server hat keine GPU; Chat und Embeddings sollen über die Alibaba Cloud Model Studio API (DashScope,
OpenAI-kompatibel) laufen. Der Betreiber hat einen Schlüssel für einen EU-Workspace (Frankfurt) geliefert. Der
Chunk-Store ist fest auf 1024 Dimensionen; Vektoren sind modellgebunden (ein Wechsel des Embedding-Modells verlangt
`tannwald:reindex`).

## Entscheid

1. **Eigenes Modul `tannwald_qwen`** mit Provider-Plugin `dashscope` auf der Kernklasse
   `Drupal\ai\Base\OpenAiBasedProviderClientBase` (drupal/ai 1.5.2, `openai-php/client` 0.22 liegt bereits im Lock) —
   keine neue Composer-Abhängigkeit. `drupal/ai_provider_openai` 1.2.5 kann zwar eine Basis-URL (`host`), ruft aber
   standardmässig vor jedem Chat `omni-moderation-latest` am selben Host, filtert die Modell-Liste auf
   `^(gpt|o1|o3|o4)` und kennt die Vektorgrösse fremder Modelle nicht.
2. **Schlüssel nur über das key-Modul**, Key-Entity `dashscope_api_key` mit Provider `env`
   (`DASHSCOPE_API_KEY_EU`); in `config/sync` steht nur der Variablenname. **Endpoint** aus `DASHSCOPE_ENDPOINT_EU`
   per `settings.php`-Override von `tannwald_qwen.settings:endpoint` (gespeichert bleibt `''`). Leer → Provider nicht
   nutzbar.
3. **Provider je Operation:** `tannwald_assistant.settings` `provider_chat` und `provider_embeddings`
   (je `ollama|dashscope`), Modelle, Dimension und Kosten unter `providers.<id>`. Der Dienst
   `tannwald_assistant.provider_resolver` ist die einzige Stelle, die Provider und Modell bestimmt (Assistent,
   Zusammenfassungen, Embeddings, Eval-Kopf); `ai.settings` `default_providers` wird nicht mehr gelesen.
4. **Fehlerbild:** Jede API-Fehlermeldung läuft durch `SecretScrubber` und wird durch eine bereinigte AI-Ausnahme
   ohne `previous` ersetzt (401/403 Setup, 429 Rate-Limit, Quota, 5xx Antwort, sonst Anfrage); Timeouts 30 s Chat,
   20 s Embeddings. Der Assistent zeigt den `limit`-Hinweis.

## Begründung

Ein Schalter je Operation erlaubt „Chat über die API, Embeddings lokal“ ohne Reindex und hält den Weg zu
API-Embeddings offen, sobald ein Endpoint mit Embedding-Modell vorhanden ist. Der Schlüssel erreicht nie
Konfiguration, Logs oder Ausnahmen.

## Konsequenzen

Stand 3.1 (2026-11-02, gemessen):

- EU-Endpoint: `GET /models` 86 Modelle, Chat `qwen-plus` (auch `qwen3-max`, `qwen3.7-plus` …), **kein
  Embedding-Modell**; `text-embedding-v3` und `text-embedding-v4` → HTTP 404 `model_not_found` („Model not exist.“).
  Embeddings bleiben bis zum Entscheid des Betreibers auf Ollama `bge-m3` (Vorschlag des Masters).
- Chat `qwen-plus` live: „bereit“ 30/2 Tokens 741 ms; Assistent-Antworten mit Zitaten 1.0–6.9 s.
- Ein Wechsel von `provider_embeddings` oder `providers.<id>.embedding_model` verlangt `drush tannwald:reindex` und
  `drush tannwald:queue-run`; das Formular warnt.
- Server (4.1): dieselben Variablennamen in `.env`; php-fpm muss die Umgebung durchreichen (`clear_env = no`).

## Nachtrag 2026-11-02/03 (Aufgaben 3.2, 3.3, 4.2 — Entscheid D11)

- **D11 = Variante 2:** Chat `qwen-plus` über DashScope EU, Embeddings `bge-m3` über Ollama — lokal auf dem Mac, auf dem Server
  als CPU-Dienst nur mit diesem Modell. Begründung: der EU-Workspace bietet kein Embedding-Modell (gemessen, oben); ein zweiter
  Schlüssel ausserhalb Europas hätte Reindex und Datenabfluss bedeutet; `bge-m3` liefert dieselben 1'024 Dimensionen, kein
  Reindex nötig. Das Formular „Assistent“ lehnt `provider_embeddings: dashscope` ab, solange der Endpoint kein Embedding-Modell
  meldet (`ProviderSettingsFormTest`). Stärkere Chat-Modelle (`qwen3-max` 404, `qwen3.7-plus` 400 „not supported in current
  workspace“) sind im Workspace nicht freigeschaltet; keine weiteren Namen probiert.
- **Eval 3b (80 Fragen, `docs/evals/ergebnisse-2026-11-02_1713.md`):** `hit@5` 0.86 (62/72), `zitat_korrekt` streng 0.48 (20/42),
  enthaltend 0.88 (37/42), `ablehnung_korrekt` 0.96 (48/50), `safety_korrekt` 0.80 (24/30, ohne Modell), p50 2.2 s / p95 7.3 s,
  0 halluzinierte Zitate. Befund: Überzitieren verwandter Kapitel (17 von 22 Fehlfällen); eine strengere Zitierregel im Prompt
  gemessen und verworfen (3/15 statt 5/15). Das Ziel 0.90 streng bleibt verfehlt und steht so im README.
- **Kosten:** Listenpreis Frankfurt USD 0.40/1.20 je Mio. Tokens (Eingabe/Ausgabe); Eval 3b CHF 0.04, alle Läufe des Tages
  CHF 0.08, Zusammenfassungen auf dem Server (31 Aufrufe, 62'518 Tokens) ≈ CHF 0.05. Konfigurierter Satz
  `providers.dashscope.kosten_pro_1k_chf` = 0.0008 (bewusst über dem Listenpreis); mit `monthly_token_limit` 2'000'000 ist der
  Deckel CHF 1.60 im Monat. Der Zusammenfassungs-Pfad schreibt noch 0.0000 CHF in die Usage-Zeile (Befund F13 aus 4.2, offen).
- **Server:** `config/sync` steht auf `provider_chat: dashscope`, `provider_embeddings: ollama` (Commit 1bce105); die
  Variablen `DASHSCOPE_API_KEY_EU` und `DASHSCOPE_ENDPOINT_EU` liest der php-fpm-Pool aus `/etc/mytannwald/env`.
